# Electro Radar

Проект мода для Minecraft 1.21.1 на NeoForge.

## Требования

- JDK 21 (64-bit)
- Gradle устанавливать отдельно не нужно: используется Gradle Wrapper.
- В игре обязательны Create и Create Big Cannons (вместе с Ritchie's Projectile Library);
  в разработке Gradle подключает их сам.

## Команды

```bash
./gradlew runClient
./gradlew build
./gradlew test   # модульные тесты решателя наведения, без запуска игры
```

Готовый мод появится в `build/libs/`.

## Shell Alarm

Сетевой потребитель отмечает снаряды больших пушек CBC, чей прогнозируемый маршрут
пересекает заданную зону. Временным предметом «Выделитель» (иконка бумаги) выберите два угла
ПКМ, поправьте грани через Ctrl+колесо и примените зону ПКМ по Shell Alarm.
Shift+ПКМ сбрасывает выделение. Сеть задаётся обычной привязкой или коммутатором.

[Использование, список опасных UUID и границы прогноза](SHELL_ALARM.md).

## Диагностика

Подробный журнал радаров (`[ElectroRadar/RadarDebug]`) по умолчанию выключен; ошибки пишутся
всегда. Его можно включить JVM-флагами без пересборки:

- `-Delectroradar.diagnostics=true` — подробные события сети, посещений секторов и мониторов;
- `-Delectroradar.diagnostics.queries=true` — дополнительно писать запросы потребителей;
- `-Delectroradar.diagnostics.visuals=true` — дополнительно писать частые клиентские события секторов.

### Проверка наведения CBC

Отдельный JVM-флаг `-Delectroradar.diagnostics.cannons=true` включает журнал
`[ElectroRadar/CannonDebug]` в серверном `logs/latest.log`; общий флаг радаров для него не нужен.
Флаг указывается **при запуске JVM**, например перед `-jar` выделенного сервера.
При выключенном флаге диагностические перехваты CBC не применяются.

- `target_selected`: UUID, тип и имя выбранной цели, её мировые координаты и центр хитбокса.
- `solution`: текущий центр цели, прогноз на запуск, скорость/ускорение, профиль пушки,
  углы, направление, целый `flightTick=n`, доля `fraction=f`, мировая `predictedHit` и невязка формулы.
  Запись производится при смене цели/статуса и не чаще раза в 20 тиков при неизменном статусе.
- `fire_attempt`: контроллер вызывает штатный `fireShot`; появление снаряда подтверждает `projectile_spawn`.
- `projectile_spawn`: реальный снаряд, его UUID, начальные координаты и скорость,
  сохранённый прогноз и точка попадания. Попытка и снаряд сопоставляются по измерению,
  месту появления с допуском 0,001 блока и времени (0–2 тика). Неоднозначные и отсутствующие
  соответствия отмечаются как `spawn_unmatched`, без назначения чужой цели снаряду.
- `flight_sample`: фактический и расчётный отрезки каждые 20 тиков и обязательно на ожидаемом
  тике попадания, положение цели в игре и расстояние от расчётной точки до реального отрезка.
- `contact`: фактический контакт CBC; `point` берётся из `BlockHitResult` для блока,
  для сущности восстанавливается пересечением sweep с расширенным хитбоксом (либо началом
  sweep при перекрытии). `outcome` различает пробитие, отскок, остановку/удаление.
  Контакт не обязательно завершает полёт и не гарантирует нанесение урона.
- `projectile_removed`: удаление/выгрузка и последняя позиция; это **не** точка попадания.
  Срабатывание взрывателя может удалить снаряд без записи `contact`.

Для сравнения используйте один `projectile` UUID от `projectile_spawn` до `contact`/`projectile_removed`.
`predictedHit` — мировая точка прогноза для целого тика `n`; `f` не добавляется ко времени движения цели.
`impactDelta` — вектор от расчётной точки до реального контакта. Фактическая начальная скорость
позволяет отделить отклонение выстрела от ошибки модели. При контакте с препятствием раньше цели
эта разница не является ошибкой баллистического решателя.

Ожидающие попытки ограничены 1024 записями, отслеживаемые снаряды — 4096;
вытеснение снаряда отмечается `tracking_evicted`. Состояние очищается при остановке сервера.
Диагностика требует проверки в игре и при включении может создавать большой журнал очередей.

### Типы орудий контроллера

- Большая пушка: выбор настильной/навесной траектории сохраняется на боковой панели.
- Автопушка: переключатель скрыт, поиск рассматривает доступные семейства в пределах времени
  жизни снаряда. Прежнее сохранённое значение переключателя не влияет на расчёт.
- Миномёт CBC (Drop Mortar): переключатель скрыт, пока используется только навесная ветвь.
  Контроллер наводит пустой ствол по штатной Drop Mortar Shell, читая её скорость и баллистику
  из актуальных свойств CBC, включая множители измерения. Поддерживается вертикальная сборка;
  мировые углы преобразуются в логические углы установки с учётом её ограничений.
  Мину загружает игрок/механизм, и выстрел после загрузки запускает сам CBC. Контроллер
  не подаёт сигнал огня миномёту и продолжает сопровождение между выстрелами.

### Проверка препятствий перед огнём

Когда затвор/таймер CBC готовы к попытке выстрела, контроллер проверяет
одну выбранную траекторию до рассчитанной точки попадания. Каждый отрезок соответствует
CBC `p_n → p_n + v_(n+1)`; последний обрезается по `f`. Первое пересечение с коллизионной
формой блока запрещает огонь и показывает «Траектория перекрыта препятствием».
Пробитие, рикошеты и разрушение препятствия не прогнозируются: любой такой блок считается преградой.
Проверяется направление фактического ствола с номинальной скоростью, без случайного разброса.

Чанки не подгружаются: незагруженная область запрещает автоматический огонь со своим статусом.
Для автопушки результат кешируется на срок до 3 тиков только при полном совпадении профиля,
положения, направления, сборки и конца проверяемого пути. Изменения блоков внутри этого короткого
окна учитываются при следующей проверке. Большая пушка свободный путь перед новой попыткой выстрела
проверяет заново; результаты с препятствием тоже имеют короткий срок жизни.

У миномёта проверяется готовность к загрузке; ручную загрузку и самостоятельный запуск мины
кодом CBC контроллер не отменяет. При включённой диагностике событие `preflight` показывает
результат (`CLEAR`, `BLOCKED`, `UNLOADED`), тик, точку и число проверенных отрезков.

### Прямой запуск через CBC

Контроллер не является источником редстоуна и может стоять с любой горизонтальной стороны
установки, если направлен на неё. После проверки цели, наведения, боеприпаса, готовности CBC
и препятствий он вызывает штатный `contraption.fireShot(level, entity)`. Расход боеприпаса,
отдача, анимация, отказы и внутренний таймер автопушки остаются в CBC. Большая пушка при
непрерывной готовности получает попытку раз в 5 тиков; автопушка сохраняет штатный темп,
соответствовавший прежнему сигналу 15. Значение темпа задаётся только внутри вызова и
восстанавливается в `finally`, включая неудачный вызов.

У установки с соседним направленным на неё **сетевым** контроллером нативный автоматический
цикл автопушки отключён: все его попытки проходят через проверки контроллера. Это отдельный
функциональный Mixin, действующий без флага диагностики. Автопушки без такого контроллера
сохраняют поведение CBC. Миномёт продолжает самостоятельно стрелять после загрузки мины.

Прямой вызов из фазы BlockEntity тика T создаёт снаряд сразу, но фаза сущностей T уже прошла.
Первый sweep выполняется в T+1, поэтому прогноз по-прежнему использует сдвиг на один тик.
Регистрация диагностической попытки выполняется до `fireShot`, чтобы синхронное появление
сущности получило правильный сохранённый прогноз.
