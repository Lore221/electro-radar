# Перехват снарядов больших пушек зенитной автопушкой

Ветка `interceptor`. Здесь анализ и математическая модель. Ядро лежит в `com.electroradar.cannon.intercept` и не зависит от Minecraft. В игру его встраивает блок «Контроллер перехвата» (§7). В игре перехват ещё не проверяли. Все факты о CBC сверены с декомпилированным CBC 5.11.7 и Minecraft 1.21.1.

## 0. Коротко

1. **CBC не умеет сбивать снаряды.**
   - `AbstractCannonProjectile.canHitEntity` отбрасывает любой `Projectile`, а `hurt()` всегда возвращает `false`. Снаряд не может ни попасть в другой снаряд, ни получить урон.
   - Штатный неконтактный взрыватель ищет цели через тот же `canHitEntity`, поэтому чужой снаряд для него невидим.
   - Значит, поражение реализует мод: своим взрывателем и своей обработкой подрыва.
2. **Траекторию чужого снаряда можно предсказать точно.** CBC при линейном сопротивлении детерминирован, а положение и скорость снаряда сервер читает с сущности. Это замкнутая формула, а не оценка.
3. **Встречу ищет уже принятый решатель B1′.** В ядре изменился только закон движения цели: интерфейс `TargetMotion` вместо равноускоренного `TargetForecast`.
4. **Поражение — свой командно-неконтактный взрыватель плюс модель осколков.**
   - Пушка при выстреле программирует взрыватель: окно взведения вокруг расчётного тика встречи и самоликвидацию после окна.
   - Подрыв происходит с упреждением, чтобы цель оказалась в осколочном конусе.
   - Вероятность поражения считается по тем же распределениям, по которым CBC разбрасывает осколки.

## 2. Время и индексы

- **Наблюдение.** Контроллер читает снаряд в фазе BlockEntity тика `t₀`. Снаряд уже сделал ход этого тика: `P(0)`, `V(0)`.
- **Ходы цели.** Ход `m` (`P(m) → P(m+1)`) идёт в фазе сущностей тика `t₀ + 1 + m`. Перед ходом CBC проверяет столкновения на отрезке `P(m) → P(m) + V(m+1)`.
- **Ходы перехватчика.** Перехватчик выпущен прямым `fireShot` в фазе BlockEntity тика `t₀ + L`. Его отрезок `n` проходит в фазе сущностей тика `t₀ + L + 1 + n`.
- **Кто ходит первым.** Чужой снаряд появился в мире раньше, поэтому в каждом тике он ходит первым. Во время отрезка `n` перехватчика цель неподвижна в `P(L + 1 + n)`.

Отсюда общий сдвиг `delay = L + d` с `d = 1`, как у задержки `CannonKind.launchDelayTicks()` для прямого огня.

Если чанк со снарядом перезагрузится, порядок обхода может смениться, и прогноз сдвинется на тик. Радиус срабатывания взрывателя должен покрывать один ход цели (см. §5.2).

## 3. Задача 1: выбор снаряда

### 3.1 Кандидаты

Кандидат — это:
- сущность, видимая радаром сети (механизм уже есть);
- класса `AbstractBigCannonProjectile`, включая мины миномёта;
- не в земле;
- с линейным сопротивлением, без `quadratic_drag`.

Снаряды автопушек и пулемётов, в том числе свои зенитные, целями не считаются.

### 3.2 Прогноз падения

По формулам §4.1 перебираются отрезки `P(m) → P(m) + V(m+1)` через ту же проверку мира, что у `WorldTrajectoryProbe`. Чанки при этом не загружаются. Результат — индекс хода падения `m_I` и точка падения.

Это `HostileShell.predictImpact`. Пробитие, рикошет и собственный взрыватель цели не моделируются: падение — граница, после которой прогноз заканчивается.

### 3.3 Угроза

Снаряд угрожает, если по прогнозу ударяется о блок внутри обороняемой зоны: шар с центром и радиусом. Свои уходящие снаряды падают далеко и отсекаются тем же правилом, без отдельного «свой-чужой».

Не считаются угрозой: уход в незагруженную область и полёт дольше проверенного горизонта, потому что падение не доказано.

### 3.4 Срочность и удержание

`slack = m_I − t_встречи` — запас между первой запланированной встречей и падением. Порядок сортировки:
1. меньший запас;
2. точка падения ближе к центру зоны;
3. выше вероятность уничтожения очередью.

Текущая цель меняется, только если другая срочнее больше чем на `switchMargin` тиков. Иначе очередь металась бы между почти равными снарядами. Реализовано в `ThreatSelector.rank/select`.

### 3.5 Несколько установок (не в прототипе)

Сеть хранит назначение «цель → установка». Распределение жадное по `slack`: каждая установка берёт самую срочную ещё не назначенную цель. Вторая установка добавляется к цели, если ожидаемая вероятность уничтожения очередью ниже порога.

## 4. Задача 2: траектория, окно огня, сопровождение

### 4.1 Точный прогноз цели

Рекурсия CBC: `a = −k·v − g·ŷ`, `p ← p + v + a/2`, `v ← v + a`. При `q = 1 − k`:

```
S(m) = (1 − q^m)/k,   A(m) = (1 − k/2)·S(m),   B(m) = (m − A(m))/k
P(m) = P(0) + A(m)·V(0) − g·B(m)·ŷ
V(m) = q^m·V(0) − g·S(m)·ŷ
```

Проверка на `m = 1`: `P(1) = P(0) + (1 − k/2)·V(0) − g/2·ŷ`, ровно один ход рекурсии. При `k = 0` получаются пределы `A = m`, `B = m²/2`.

Коэффициенты считает `FlightCoefficients` профиля с единичной скоростью и гравитацией (`LinearDragMotion`). Поэтому прогноз чужого снаряда идёт той же устойчивой арифметикой (`expm1`, ряд для малых `k·m`), что и полёт собственного.

Граница смещения цели за тик, на которой держится безопасный пропуск тиков решателя:

```
|P(m+1) − P(m)| = |(1 − k/2)·V(m) − g/2·ŷ| ≤ |V(0)| + g·S(m) + g/2
```

### 4.2 Условие встречи

Отрезок перехватчика в тик `n`: `(R(n) + f·U(n))·u − (g·B(n) + f·w(n))·ŷ`, `f ∈ [0, 1]`. Он должен пройти через `X(n) = P(L + 1 + n) − C`, где `C` — центр пушки.

Это в точности задача ядра B1′: квадратное уравнение по `f` для каждого тика и доказуемый пропуск тиков по запасу. Ядро не менялось. Цель передаётся как `HostileShell.asTarget(C, L + 1)`, реализация `TargetMotion`.

### 4.3 Перебор момента пуска и горизонт

Для `L = 0, 1, …` горизонт перехватчика обрезается сроком цели: `L + 1 + n ≤ m_I − margin` (новая граница `FlightHorizon.Bound.DEADLINE`, метод `until`). Пустой результат на таком горизонте доказывает, что при этом `L` встречи до падения нет.

Дополнительные условия встречи:
- `n ≥ minInterceptTick` — взведение взрывателя;
- дальность встречи от пушки не меньше `minInterceptRange`, чтобы подрыв был не над своими.

### 4.4 Разворот и окно огня

Время разворота по оси из покоя при скорости `ω` и ускорении `α`:

```
θ ≤ ω²/α:  t = 2·√(θ/α)
иначе:     t = θ/ω + ω/α
```

Оси вращаются одновременно, поэтому берётся максимум из двух. Плюс `settleTicks` на дотягивание пропорционального привода (`SlewModel`).

- **Окно открывается** при первом `L`, для которого встреча есть и `t_разворота ≤ L`.
- **Окно закрывается**, когда встреч больше нет: снаряд упадёт раньше или уйдёт за досягаемость перехватчика (время жизни 60 ходов у стали).

Статусы:
- `FEASIBLE` — окно открыто, очередь запланирована;
- `TOO_LATE` — встречи есть, но установка не успевает до их окончания;
- `NO_SOLUTION` — встречи нет ни при каком моменте пуска до падения.

### 4.5 Сопровождение огнём

Выстрелы ставятся не чаще перезарядки (4 тика на темпе 15). Следующий выстрел принимается, если требуемое направление сместилось не больше чем на `ω·Δt`. Подсказка тика предыдущей встречи держит очередь на одной ветви решения, без прыжков LOW/HIGH.

План — это только расписание. В бою решение пересчитывается каждый тик по свежему состоянию цели, как сейчас делает контроллер наведения. Очередь прекращается, когда цель исчезла (уничтожена или упала) или окно закрылось.

### 4.6 Разброс

С двух стволов у стальной автопушки разброс равен 0, и выстрел детерминирован. Иначе на дальности `r` разброс по каждой оси треугольный с полушириной `r·0,0172275·spread`, его СКО — `r·0,0172275·spread/√6`.

Пример: `spread = 3` на 100 блоках даёт СКО около 2,1 блока. С таким разбросом нужен заметный радиус срабатывания взрывателя.

### 4.7 Стоимость

- **Расчёт боя.** На цель приходится до ~100 вариантов `L`, каждый — один доказуемый поиск по горизонту до 60 тиков с пропусками. Считается при захвате цели и периодически.
- **Сопровождение.** Один поиск в тик с подсказкой.
- **Бюджет.** `InterceptSearch` уже поддерживает бюджет и продолжение, если целей много.

## 5. Задача 3: механизм уничтожения

### 5.1 Почему свой взрыватель

Штатные взрыватели CBC чужой снаряд не видят (§1). Подкласс `FuzeItem` получает те же хуки, что штатные: `onProjectileTick`, `onProjectileClip`, `onProjectileExpiry`. Если вернуть `true`, CBC сам вызывает `detonate`, то есть фугасный взрыв и осколочный конус. Mixin не нужен.

### 5.2 Командно-неконтактный взрыватель (`InterceptFuze`)

- **Программа.** Это тик встречи `n*`, взведение с `n* − w`, самоликвидация в `n* + w + 1`, радиус срабатывания `ρ` и упреждение `λ`.
- **Как задаётся.** Программа пишется при выстреле в серверный реестр «снаряд → программа». `EntityJoinLevelEvent` срабатывает синхронно внутри `fireShot`; тот же приём уже использует диагностика наведения. `ItemStack` патрона не меняется.
- **Срабатывание.** В отрезке `n` цель неподвижна. Если расстояние от неё до отрезка не больше `ρ`, взрыватель срабатывает. Точка подрыва отступает назад по отрезку на `λ`, но не дальше его начала.
  Осколки летят конусом вперёд. При подрыве в точке сближения цель оказалась бы сбоку от конуса, а после отступа она на его оси.
- **Самоликвидация.** Промах взрывается в воздухе после окна и не падает на своих.
- **Выбор `ρ`.** Радиус должен покрывать ошибки:
  - один ход цели при смене порядка обхода (§2);
  - разброс (§4.6);
  - неточность наведения привода.

### 5.3 Модель поражения (`FragmentKillModel`)

- **Фугасная зона.** Цель на расстоянии не больше `blastRadius` уничтожается, если её `durability_mass ≤ blastMaxDurability`. Оба значения — параметры мода. По умолчанию предлагается радиус 2 и прочность 2: фугасный снаряд (HE) поражается, бронебойная болванка (AP) нет.
- **Осколки.** Когда осколок продвинулся вперёд на `d`, его боковое смещение равно `d·s·(t₁·r + t₂·u)`. От скорости осколка оно не зависит.
  - Цель с половиной размера `a` впереди на `d` и со смещением `(y₀, z₀)` задета одним осколком с вероятностью:
    ```
    p = P(|w·t₁ − y₀| ≤ a) · P(|w·t₂ − z₀| ≤ a),   w = d·s·cos(угла места)
    ```
    где `t` — треугольные на `[−1, 1]`.
  - Цель вне досягаемости осколков, если `d > 1,4·|v|·5`.
  - Уничтожение требует `m = ⌈durability_mass / 0,75⌉` попаданий: 3 для HE, 11 для AP. Вероятность — хвост биномиального распределения `P(Bin(15, p) ≥ m)`.
- **Очередь.** `P = 1 − Π(1 − pᵢ)`.

Примеры при `a = 0,4` и угле места 30°:

| Упреждение `d` | `p` на осколок | HE (m = 3) | AP (m = 11) |
|---|---|---|---|
| 3 блока | 0,73 | ≈ 1,0 | ≈ 0,5 |
| 10 блоков | 0,11 | ≈ 0,23 | ≈ 0 |

Вывод: упреждение 2–4 блока. AP-болванку зенитным огнём почти не взять, и это естественный баланс.

Упрощения модели:
- цель считается неподвижной, пока до неё летят осколки (они в 2–3 раза быстрее);
- гравитация осколков не учитывается (≤ 0,3 блока за 5 тиков);
- не учитывается начальный разброс ±0,0625.

### 5.4 Применение поражения (адаптер, не в прототипе)

В хуке взрывателя, перед возвратом `true`:
1. найти снаряды больших пушек в радиусе досягаемости осколков;
2. для каждого посчитать вероятность из §5.3, бросить случайное число;
3. при поражении — `discard()` с визуальным взрывом без разрушения блоков.

Есть вариант «подорвать фугас в воздухе». `detonate` у снарядов CBC защищённый, так что понадобится access transformer или mixin. Это решение за архитектором.

## 7. Встраивание

### 7.1 Сделано: контроллер перехвата

Блок `intercept_controller`: модель и текстура как у контроллера наведения. Ставится лицевой стороной к установке с автопушкой и привязывается к сети так же.

- **Цель.** Снаряд, выбранный на мониторе сети. Угрозу контроллер не оценивает, `ThreatSelector` не используется. Цель — `AbstractBigCannonProjectile` в полёте с линейным сопротивлением (`BigCannonShell`), иначе статус «эту цель нельзя обстреливать».
- **Орудие.** Только автопушка (`WRONG_CANNON`) с зенитными патронами (`FLAK_REQUIRED`), в которые поставлен взрыватель перехвата (`INTERCEPT_FUZE_REQUIRED`). Патрон в ленте — гильза CBC, взрыватель читается у снаряда внутри неё. Как и контроллер наведения, сетевой контроллер забирает у CBC автоматический запуск соседней автопушки (`CbcDirectControl`).
- **Срок полёта.** `HostileShell.predictImpact` до 400 ходов (`ShellImpactForecast`). Прогноз держится, пока снаряд идёт по нему (отклонение до 0,25 блока), и пересчитывается раз в 20 тиков.
- **Сопровождение.** Каждый тик ищется встреча при выстреле сейчас (`EngagementPlanner.immediate`, `L = 0`, без проверки разворота). К ней установку ведёт `AimDrive` контроллера наведения. Огонь разрешается по фактическому направлению ствола. Допуск — угол, под которым видна половина радиуса срабатывания на дальности встречи. Перед попыткой выстрела проверяется свободный путь.
- **Окно.** Если встречи сейчас нет, `EngagementPlanner.plan` (раз в 5 тиков) ищет окно. При `FEASIBLE` установка заранее разворачивается к первому выстрелу (`WINDOW_PENDING`), иначе статус `TOO_LATE` или «цель недосягаема».
- **Взрыватель перехвата** (`InterceptFuzeItem`, подкласс `FuzeItem`). Ставится в зенитный патрон штатным рецептом CBC `munition_fuzing`: рецепт принимает любой `FuzeItem`.
  - Программа записывается в реестр `ProgrammedFuzes` «снаряд → программа» внутри `fireShot` через `EntityJoinLevelEvent`; патрон не меняется.
  - После хода снаряда CBC вызывает `onProjectileTick`. Отрезок берётся от `xo/yo/zo` до текущего положения, положение цели читается из мира.
  - При срабатывании вызывается штатный `detonate` CBC (mixin-invoker) с упреждением `λ` и ставится `removeNextTick`. После окна взрыватель возвращает `true`, и CBC подрывает снаряд в текущем положении.
  - Без программы (ручной огонь, контроллер наведения) взрыватель работает как ударный (кроме рикошета) и подрывается в конце времени жизни.
  - Иконка пока временная — `proximity_fuze` CBC. Рецепта крафта нет, как и у остальных предметов мода.
- **Поражение.** Для каждого снаряда большой пушки в досягаемости осколков — бросок по `FragmentKillModel`. При поражении снаряд удаляется (`discard`) с частицей взрыва, блоки не разрушаются.
- **Правила** (`InterceptControllerBlockEntity.POLICY`, пока константы):

  | Параметр | Значение |
  |---|---|
  | Поиск окна вперёд | 100 тиков |
  | Запас до падения | 2 тика |
  | Взведение не раньше | 2-го отрезка |
  | Безопасная дальность встречи | 16 блоков |
  | Окно взрывателя | ±3 тика |
  | Радиус срабатывания `ρ` | 3 блока |
  | Упреждение `λ` | 3 блока |
  | Фугасная зона | 2 блока, прочность ≤ 2 |

### 7.2 Следующие шаги

1. **Автовыбор цели.** `ThreatSelector` вместо ручного выбора на мониторе: обороняемая зона, монитор показывает назначение и даёт ручной приоритет.
2. **Серверный конфиг:** `ρ`, `λ`, `w`, фугасная зона, `minInterceptRange`, `margin`, `switchMargin`.
3. **Диагностика.** События `intercept_plan`, `fuze_detonation`, `kill_roll` в `CannonDiagnostics`.
4. **Тесты ядра** (когда будет разрешено):
   - `LinearDragMotion` против пошаговой рекурсии;
   - планировщик на синтетических траекториях;
   - формула осколков против Монте-Карло по `spawnConeBurst`.

## 8. Риски и вопросы архитектору

- **Задержка обнаружения.** Обзорный радар обходит зоны по циклу. Снаряд в полёте живёт 50–150 тиков, и поздний захват съедает окно. Нужна оценка цикла против времени полёта.
- **Где прогноз ломается:**
  - вода (сопротивление умножается на плотность);
  - рикошет и пробитие;
  - собственный взрыватель цели;
  - квадратичное сопротивление (такие снаряды не поддерживаются).

  Защита — пересчёт каждый тик.
- **Порядок обхода** после перезагрузки чанка — сдвиг на тик, покрывается `ρ`.
- **Решения за архитектором:**
  - `discard` или подрыв в воздухе;
  - где задаётся обороняемая зона;
  - автоматический или ручной выбор цели;
  - баланс фугасной зоны.
