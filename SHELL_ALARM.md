# Shell Alarm

Реализация в `feature/shell-alarm` поверх `interceptor` (`c910127`). Перед реализацией
изучен `INTERCEPTOR_MODEL.md`; используются общие `BigCannonShell`, `HostileShell` и `LinearDragMotion`.

## Использование

Shell Alarm и временный предмет `???` находятся в творческой вкладке Electro Radar.
Модель, `shell_alarm.png` и `shell_alarm_display.png` перенесены из Power Radar;
для предмета выделения используется стандартная иконка бумаги без окончательного имени.

1. Привяжите предмет Shell Alarm к сети ПКМ по радару и установите его, либо подключите
   установленный блок коммутатором (`linker`). Это обычный `EndpointRole.CONSUMER`.
2. Предметом `???` выберите два противоположных угла ПКМ по блокам. Оба блока входят
   в объём; один выбранный блок даёт зону 1×1×1. ПКМ в воздухе выбирает точку в 16
   блоках перед глазами, поэтому верхний угол можно задать без временной постройки.
3. После второго угла зона автоматически записывается в предмет и подсвечивается
   голубым контуром. Ctrl+колесо на выбранной грани расширяет/сужает её на один блок.
4. ПКМ готовым предметом по Shell Alarm применяет копию зоны. Предмет не расходуется.
   Зона сохраняется в BlockEntity, а не как ссылка на предмет. Изменение предмета
   не изменяет прибор, пока план не применён повторно.
5. Shift+ПКМ предметом сбрасывает выделение для создания новой зоны. Применённая
   в Alarm копия при этом остаётся. Повторное применение заменяет её.

Граница абсолютная, трёхмерная, привязана к измерению. Переносить её относительно
положения Alarm автоматически нельзя. Без зоны прибор показывает «Защитная зона не
задана». В другом измерении применение отклоняется. Максимальная сторона — 2048
блоков, высота ограничивается высотой текущего мира. Ни выделение, ни применение
не читают содержимое области и не подгружают её чанки.

Контур принятой зоны зелёный при наведении на Alarm с предметом выделения в руке.
В очках Create видны статус, количество опасных снарядов и размеры области.
При наличии опасных UUID блок выдаёт редстоун 15, после очистки списка — 0.

## Контракт классификации

- Кандидаты приходят только из `ConsumerConnection.queryTargets` текущей сети,
  с `AVAILABLE` sample (включая обычную память сети), в текущем измерении.
  По этому разрешённому набору UUID читаются живые сущности, как у Target Controller.
  Собственных spatial scans, новой сети и изменений ручного выбора нет.
- Поддерживаются только `AbstractBigCannonProjectile`, включая мины; автопушка,
  стрелы, игроки и прочие сущности не анализируются. Снаряды в земле исключаются.
- Проверяется будущий свободный маршрут против выбранного объёма. Обе геометрии CBC
  учитываются явно: collision sweep `P[n] → P[n]+V[n+1]` и перемещение
  `P[n] → P[n+1]`. Это предотвращает пропуск зоны в зазоре между ними.
- Зона расширяется только на половину максимального размера hitbox снаряда,
  аналогично reach в CBC. Дополнительного радиуса взрыва и определения свой/чужой нет.
  В частности, снаряд, выпущенный изнутри зоны, может считаться опасным, пока его
  будущий маршрут пересекает эту область.
- Ландшафт, пробития, рикошеты впереди и собственный взрыватель цели не прогнозируются:
  снаряд за стеной может считаться потенциально опасным. Это оценка пересечения
  объёма, а не доказанное будущее попадание. Никакого управления пушками здесь нет.

Общий адаптер `BigCannonShell` снимает текущие координаты центра hitbox и мгновенную скорость
в фазе BlockEntity, после обновления сущности. Используются параметры CBC с
множителями измерения и флагом отсутствия гравитации. Вход в жидкость, квадратичное
сопротивление и неподдерживаемые параметры дают неполный прогноз, а не «безопасно».
Уже находящийся внутри зоны снаряд отмечается сразу, даже при неподдерживаемой
физике или исчерпанном бюджете прогноза.
Зафиксированное наблюдение задаёт модель для любых будущих индексов; последовательная
проверка маршрута использует дешёвую рекурсию CBC без запросов блоков мира.

## Список UUID и кэш

```java
Set<UUID> dangerous = alarm.dangerousProjectiles();
```

Это текущий неизменяемый серверный набор опасных снарядов одного Alarm. Он обновляется
в его серверном BlockEntity tick, не сохраняется в NBT и не отправляется клиентам.
На клиент передаются только зона, статус и счётчик для очков. Приборы могут защищать
разные объёмы, поэтому глобальная метка в `ObservationClassification` не меняется.

Прогноз кешируется для UUID, состояния движения и геометрии зоны. На обычном кадре
проверяются позиция и скорость против замкнутой модели; повторный обход маршрута
не выполняется. Изменение движения, профиля, размера или зоны инвалидирует результат.
Возраст берётся из `entity.tickCount`, чтобы остановка тиканья сущности не выглядела
как выполненные шаги полёта. Сброс возраста при перезагрузке также создаёт новый прогноз.

Потеря обнаружения в разрешённом снимке, удаление/застревание сущности, отключение
сети и выгрузка Alarm очищают соответствующие результаты. Чужие UUID из предыдущей
сети не переносятся в новую. Изменение зоны пересчитывает уже известные снаряды.

За тик выполняется до 8 новых прогнозов на Alarm. Предел одного прогноза — 4096
обновлений, но он завершается раньше, если дальнейший вход геометрически исключён.
Исчерпание бюджета/горизонта и неподдерживаемая физика дают статус неполного прогноза.
У неполного прогноза горизонт обновляется по мере движения; отсутствие пересечения
в конечном горизонте не доказывает бесконечную безопасность. UUID попадает в опасный
набор при найденном будущем пересечении либо непосредственно обнаруженном текущем.

## Проверка

```bash
./gradlew build
```

Модульные проверки не требуют запуска Minecraft. Проверяются быстрый пролёт через
тонкую зону, обе геометрии CBC, падение после высокого пролёта, взлёт снизу, размер
снаряда, ограниченный горизонт, зависание, сравнение со случайными потиковыми
траекториями и независимой геометрией граней. Отдельно проверяются кэширование,
удаление/перепривязка UUID, изменение профиля и зоны, бюджеты, обновление неполного
горизонта и границы редактора.

В игре ещё требуется проверить взаимодействие рук/предметов, визуальное выделение
и изменение граней, загрузку мира, коммутатор, редстоун и несколько Alarm в разных
сетях на живых снарядах CBC. Автоматические проверки не заменяют эту проверку.
